## Порождающие паттерны (Creational)
*Эти паттерны отвечают за механизмы создания объектов, позволяя сделать систему независимой от способа создания и представления объектов.*

* **Singleton (Одиночка)** — гарантирует, что у класса есть только один экземпляр.
* **Factory Method (Фабричный метод)** — определяет интерфейс для создания объекта, но оставляет подклассам решение о том, какой класс инстанцировать.
* **Abstract Factory (Абстрактная фабрика)** — предоставляет интерфейс для создания семейств связанных объектов.
* **Builder (Строитель)** — отделяет конструирование сложного объекта от его представления.
* **Prototype (Прототип)** — позволяет копировать существующие объекты, не вдаваясь в подробности их реализации.

## Структурные паттерны (Structural)
*Эти паттерны рассматривают, как из классов и объектов образуются более крупные структуры.*

* **Adapter (Адаптер)** — позволяет объектам с несовместимыми интерфейсами работать вместе.
* **Bridge (Мост)** — разделяет абстракцию и реализацию так, чтобы они могли изменяться независимо.
* **Composite (Компоновщик)** — позволяет сгруппировать объекты в древовидную структуру для работы с ними как с единым целым.
* **Decorator (Декоратор)** — позволяет динамически добавлять объектам новую функциональность.
* **Facade (Фасад)** — предоставляет простой интерфейс к сложной системе классов.

## Поведенческие паттерны (Behavioral)
*Эти паттерны заботятся об алгоритмах и распределении обязанностей между объектами.*

* **Strategy (Стратегия)** — определяет семейство алгоритмов, инкапсулируя каждый из них.
* **Observer (Наблюдатель)** — создает механизм подписки, позволяющий одним объектам следить и реагировать на события в других объектах.
* **Command (Команда)** — превращает запросы в объекты, позволяя передавать их как аргументы.
* **State (Состояние)** — позволяет объектам менять поведение в зависимости от своего состояния.
